How it fits together

A graph platform that stays out of your domain.

Your model, your words, your layout policy. The library supplies the graph core, the adapter contract, three renderers and the generic modules a graph interface needs. This page is the map; the live demo next door makes it move.

Four moves

01

Describe

Keep nodes, edges and levels in your own vocabulary. No library types leak in.

02

Adapt

Map your model to the shared RenderModel once. Positions and labels come from here.

03

Render

Mount WebGL, Cytoscape or static SVG over the same RenderModel. Swap at runtime.

04

Drive

Bind a controller for selection, search, bands and trail; layer navigation and a11y over it.

1. Describe your domain

src/model.ts defines a release pipeline. Its stages, lanes and statuses are application words. The library never sees them until they are mapped. 

import { buildModel, type BuildModel } from './model'

const model: BuildModel = buildModel()
// nodes → { id, label, kind, stage, lane, outcome, size, status }
// edges → { id, source, target, kind, confidence }

2. Map once to the contract

src/host.ts owns the adapter. It turns the domain model, a layout and a level into one renderer-agnostic RenderModel. 

const adapter = new BuildAdapter(adapterConfig(() => placed()))

const renderModel = adapter.build(model, {
    level, positions, focus, bands, edges: true,
    laneLabels, axisLabels,
})

3. Mount any renderer

The live page switches between three renderers with one click. They all consume the same object; none of them knows what a release stage is. 

import { SpaceGraphRenderer } from '@spacegraphjs/spacegraph-renderer'

const renderer = new SpaceGraphRenderer()
await renderer.mount(canvas, { theme, projection: '2d' })
host.controller.bind(renderer)

// CytoscapeRenderer and InlineGraph (static SVG) take the same model.

4. Bind interaction and generic modules

Selection, search, minimap, trail, zoom bands, accessibility and overlays are bound to the host model. The gallery on the live page runs each one and shows its output. Plugins can be looked up by id, instance or class; `requirePlugin` reports a missing one instead of returning nothing, and `pluginManager.use(plugin)` registers and initializes a plugin added after create. 

import { GraphController } from 'spacegraphjs/control'

const controller = new GraphController({
    bands: { bands, hysteresis: 0.02 },
})
controller.select(['test:failure'])

Run it, check it, ship it

One pnpm workspace consumer owns the pages, their config, their tests and the published package proof. No external assets or services are needed. 

pnpm --filter demo dev          # http://localhost:5173
pnpm --filter demo test         # capability suite (Vitest)
pnpm --filter demo test:e2e     # browser suite (Playwright)
pnpm run build:demo             # → dist-demo/

The build emits relative asset paths, so the contents of dist-demo/ can be uploaded to a domain root or a project subpath unchanged.
